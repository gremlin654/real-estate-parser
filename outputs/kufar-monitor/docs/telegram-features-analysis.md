# Telegram Bot Features — Анализ и предложения по развитию

## Контекст проекта

**Kufar Monitor** — система мониторинга недвижимости с Telegram Bot v4.0 (aiogram 3.x). Бот уже реализует базовую функциональность подписки на уведомления о новых квартирах и падениях цен.

---

## Текущая реализация (v4.0.x)

### Уже реализовано

| Функция | Описание |
|---------|----------|
| `/start` | Регистрация пользователя |
| `/help` | Справка по командам |
| `/stop` | Деактивация пользователя |
| `/subscribe` | FSM wizard: город → комнаты → валюта → цена → м² → этаж → price_drop → deal_score → подтверждение |
| `/settings` | Просмотр, редактирование, удаление подписок |
| `/unsubscribe` | Удаление всех подписок |
| Price Drop уведомления | Уведомления только о падении цены |
| Deal Score фильтр | Порог выгодности объявлений |
| Rate Limiting | 20/час на пользователя (Redis + PostgreSQL fallback) |
| Дедупликация | Уникальный индекс по (user_id, listing_id, subscription_id, event_type) |
| Graceful shutdown | Корректная остановка scheduler |
| Логирование | Cleanup уведомлений старше 30 дней |

## Предложения по развитию

### P0 — Критически важные

#### 1. Поддержка Web App (Mini App)

**Описание:** Интеграция Web App для расширенного управления подписками через UI.

**Реализация:**
- Создание Telegram Web App (`/webapp` endpoint)
- Полный CRUD подписок в UI
- Просмотр истории уведомлений
- Статистика по подпискам

**Пользовательский сценарий:**
```
Пользователь → /start → "Открыть расширенные настройки" → Web App с UI
```

**Техническая реализация:**
```python

# Telegram keyboard

```

**Приоритет:** P0  
**Сложность:** Высокая  
**Зависимости:** Frontend React app

#### 2. Продвинутые фильтры подписки

**Описание:** Расширение параметров подписки.

| Параметр | Описание | Формат |
|----------|----------|--------|
| `area_min` / `area_max` | Площадь квартиры (м²) | int |
| `floor_first_only` | Только первый этаж | bool |
| `floor_last_only` | Только последний этаж | bool |
| `not_ground_floor` | Исключить первый этаж | bool |
| `house_type` | Тип дома (кирпичный/панельный/монолит) | enum |
| `renovation` | Ремонт (евро/косметический/без) | enum |
| `balcony` | Наличие балкона/лоджии | bool |

**Пользовательский сценарий:**
```
/subscribe → площадь → этаж предпочтения → тип дома → ремонт → подтверждение
```

**Приоритет:** P0  
**Сложность:** Средняя  
**Зависимости:** Kufar API расширенные данные

#### 4. Уведомления об изменениях (Price Watch)

**Описание:** Отслеживание конкретных объявлений и уведомления об изменениях.

**Сценарии:**
- Кто-то из пользователей нашёл интересную квартиру → добавил в "наблюдение"
- Цена изменилась → уведомление
- Квартира обновлена (описание, фото) → уведомление
- Квартира удалена → уведомление

**Реализация:**
```python
# Новая таблица
class WatchList(Base):
    id: UUID
    user_id: FK(TelegramUser)
    listing_id: FK(Listing)
    created_at: DateTime

# Команды
/watch - добавить объявление в наблюдение
/my_watches - показать наблюдаемые объявления
/unwatch {listing_id} - удалить из наблюдения
```

**Приоритет:** P1  
**Сложность:** Средняя

#### 8. Групповые подписки

**Описание:** Подписки для группы людей (семья, риелтор с клиентами).

**Сценарий:**
- Создание группы: `/group create {name}`
- Добавление участников: `/group add @username`
- Подписки применяются ко всей группе
- Уведомления приходят всем участникам

```python
class TelegramGroup(Base):
    id: UUID
    name: str
    owner_id: FK(TelegramUser)
    created_at: DateTime

class TelegramGroupMember(Base):
    group_id: FK(TelegramGroup)
    user_id: FK(TelegramUser)
    role: Enum(admin/member)
```

**Приоритет:** P2  
**Сложность:** Высокая

### Инфраструктура
- Redis: уже используется, расширить кэширование
- PostgreSQL: добавить новые таблицы
- Frontend: React Web App для Telegram

### API Endpoints для Web App
```bash
GET    /api/v1/telegram/subscriptions    # Список подписок
POST   /api/v1/telegram/subscriptions   # Создать подписку
PUT    /api/v1/telegram/subscriptions/{id}  # Обновить
DELETE /api/v1/telegram/subscriptions/{id}  # Удалить

GET    /api/v1/telegram/watches         # Наблюдаемые
POST   /api/v1/telegram/watches         # Добавить в наблюдение
DELETE /api/v1/telegram/watches/{id}    # Удалить из наблюдения

GET    /api/v1/telegram/stats           # Статистика пользователя

GET    /api/v1/telegram/webapp/config   # Конфиг для Web App (города, валюты,...)
```

### База данных (новые таблицы)
```sql
-- Watch list
CREATE TABLE telegram_watches (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES telegram_users(id) ON DELETE CASCADE,
    listing_id UUID REFERENCES listings(id) ON DELETE CASCADE,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(user_id, listing_id)
);

-- Groups (optional)
CREATE TABLE telegram_groups (
    id UUID PRIMARY KEY,
    name VARCHAR(100),
    owner_id UUID REFERENCES telegram_users(id),
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE telegram_group_members (
    group_id UUID REFERENCES telegram_groups(id) ON DELETE CASCADE,
    user_id UUID REFERENCES telegram_users(id) ON DELETE CASCADE,
    role VARCHAR(20) DEFAULT 'member',
    PRIMARY KEY (group_id, user_id)
);
```
